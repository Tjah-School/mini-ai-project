# Software

## Numbers

**32-Bit Signed Integer:** A signed integer format using 32 bits, capable of representing values up to `2,147,483,647` ($2^{31} - 1$).  
**4GL (Fourth-Generation Language):** Higher-level languages built for specific domains (such as database querying with SQL) that specify desired outcomes with less procedural boilerplate.  

## A

**Abstraction:** Reducing complexity by hiding underlying implementation details and exposing only relevant concepts or interfaces.  
**Acceptance Test:** Validation testing to confirm the software meets business or customer requirements before sign-off.  
**ACID Properties:** Atomicity, Consistency, Isolation, and Durability—properties that ensure reliable database transaction processing.  
**Agile:** An iterative, collaborative approach to software development emphasizing short release cycles, adaptability, and frequent feedback.  
**Application Software:** Programs designed to perform specific tasks for end users, such as web browsers, word processors, media players, and video games, relying on system software to execute.  
**ASCII:** A character encoding standard that maps characters (such as letters, digits, and punctuation) to numeric values and binary representations. **Assembler:** A program that translates assembly language mnemonics into machine code.  
**Assembly Language:** A low-level programming language closely tied to a processor's architecture that uses symbolic instructions instead of raw binary.  
**Atomicity:** The transaction property ensuring all operations in a transaction succeed together or none take effect.  

## B

**Batch System:** An early operating system model where jobs are grouped and run sequentially without interactive user input during execution.  
**Binary:** A base-2 numeral system using `0` and `1`, corresponding to two electrical states (`OFF` and `ON`) in digital hardware.  
**Bit:** A single binary digit (`0` or `1`), representing the basic unit of digital information.  
**Black-Box Testing:** Testing software based on inputs and expected outputs without examining internal code structure.  
**Branch:** An independent line of development in version control that allows isolated changes before merging.  
**Bytecode:** An intermediate, lower-level representation of code designed to be executed efficiently by a virtual machine or runtime engine rather than directly by physical hardware.  

## C

**Column (Attribute):** A named field in a table representing a specific property or data element of each record.  
**Commit:** A recorded snapshot of changes saved to a version control history along with metadata such as a message.  
**Compiled Binaries:** Executable files produced by compiling source code, distributed without exposing the underlying human-readable source.  
**Compiler:** A translator that converts an entire source program into target code (often machine code or bytecode) prior to execution.  
**Context Switch:** The process of saving the execution state of a running process and loading the saved state of another process so the CPU can switch tasks.  
**Control Structures:** Constructs—such as conditional branching and loops—that determine the order in which instructions execute.  
**Copyleft Licence (e.g., GPL):** A licensing approach requiring derivative or distributed works to remain under the same (or compatible) open license terms.  
**CPU (Central Processing Unit):** The primary processor that executes program instructions and performs arithmetic and logical operations.  

## D

**Data Types:** Classifications that define what kind of values a piece of data can hold and what operations are valid on it.  
**Database:** A structured collection of organized data stored for efficient retrieval and management.  
**DBMS (Database Management System):** Software that creates, stores, queries, updates, and administers databases while enforcing access and integrity rules.  
**Declarative / Logic Programming:** A paradigm where programs express *what* result or relationship is desired rather than detailing explicit control flow.  
**Deploy:** Pushing built software to target environments or servers so users can access or run it.  
**Derivative Works:** Software created by adapting, modifying, or building upon existing software.  
**Device Driver:** System software that enables the operating system to communicate with and control specific hardware peripherals, such as a graphics card or storage device.  
**Distributed System:** A collection of independent computers connected over a network that coordinate to function as a cohesive system.  

## E

**Encapsulation:** Bundling data and related methods within an object while restricting direct external access to internal state.  

## F

**Foreign Key (FK):** A column or set of columns in one table that references the primary key of another table to link records across tables.  
**Fork:** Creating an independent copy of a codebase to pursue a separate development path.  
**Freeware:** Software distributed at no monetary cost, though not necessarily open source or accompanied by source code rights.  
**Functional Programming:** A paradigm emphasizing pure functions and immutable data while minimizing side effects and mutable state.  

## G

**Git:** A widely used distributed version control system created for Linux kernel development.  
**GPU (Graphics Processing Unit):** Specialized hardware designed to accelerate graphics rendering, image processing, and parallel computations.  

## H

**Hardware:** The physical components of a computing system, such as processors, memory chips, storage drives, and input/output devices.  
**High Cohesion:** A design quality where elements within a module belong together and serve a single, well-defined responsibility.  
**High-Level Code:** Human-readable programming code written with structured syntax and abstractions (such as Python, C++, or Java) rather than raw hardware instructions.  
**Hybrid Cloud:** A deployment model combining two or more distinct cloud infrastructures (such as private and public) while preserving data and application portability.  

## I

**IaaS (Infrastructure as a Service):** A cloud service model providing fundamental compute, storage, and network resources on demand.  
**If/Else (Selection):** Conditional branching that chooses which code path to execute based on whether a condition evaluates to true or false.  
**Imperative / Procedural Programming:** A paradigm focused on explicit step-by-step statements and procedures that change program state over time.  
**Information Hiding:** Concealing internal module details behind a defined interface so external components do not depend on internal implementation.  
**Inheritance:** An OOP mechanism allowing a class or object to derive attributes and behaviors from an existing parent class.  
**Intangible:** Existing as digital information or rules rather than a physical object that can be touched.  
**Integration Test:** Testing combined modules to verify their interactions and data exchange work as expected.  
**Interpreter:** A translator that reads, analyzes, and executes source code step-by-step or line-by-line during runtime.  
**Iterative / Incremental:** Developing a system in repeated cycles and/or progressive increments that add functionality over time.  

## J

**JIT (Just-In-Time Compilation):** Compiling portions of bytecode or interpreted code into native machine code during execution to improve runtime performance.  
**JOIN:** A relational/SQL operation that combines rows from two or more tables based on related columns, typically keys.  

## L

**Lexical Analysis (Tokens):** The initial compilation phase that scans source text and groups characters into meaningful units called tokens.  
**Linux Kernel:** The central core of a Linux operating system that manages hardware resources, memory, and processes.  
**Loops (Iteration):** Repeating a block of instructions while a condition holds or across a collection of items.  
**Low Coupling:** A design quality where modules have minimal dependencies on one another, reducing ripple effects when changes occur.  

## M

**Machine Code:** Low-level binary instructions directly executed by a CPU's hardware circuitry.  
**Measured Service:** Monitoring, controlling, and reporting resource usage to provide transparency and usage-based billing.  
**Memory Allocation:** Assigning regions of main memory to running processes.  
**Memory Protection:** Hardware and OS enforcement preventing one process from reading or writing memory belonging to another process or the OS.  
**Merge:** Integrating changes from one branch into another.  
**Mnemonics:** Short symbolic names or abbreviations (such as `MOV` or `ADD`) representing low-level instructions in assembly language.  
**Modularity:** Dividing a software system into distinct modules with clear boundaries to improve maintainability and parallel development.  
**Multiprogramming / Multitasking:** Techniques that allow multiple programs to reside in memory and advance concurrently by rapidly switching execution across them.  

## N

**Normalisation:** Structuring relational tables to minimize data redundancy and prevent update anomalies.  
**NoSQL:** Non-relational database approaches designed for flexible schemas, distributed scale, or specialized data models beyond traditional tabular relations.  

## O

**Object-Oriented Programming (OOP):** A paradigm that organizes software around objects encapsulating state (data/attributes) and behavior (methods).  
**Open-Source Software:** Software whose source code is made available under terms meeting open-source criteria, allowing inspection, modification, and redistribution.  
**Operating System (OS):** Core system software that coordinates hardware resources, manages processes and memory, and provides an interface for users and applications.  
**Overflow:** A condition occurring when a calculation produces a value outside the representable range of a fixed-size numeric type, potentially causing wrap-around or errors.  

## P

**PaaS (Platform as a Service):** A cloud service model providing a managed platform and runtime environment where developers deploy and run their own applications.  
**Page Fault:** An event triggered when a program accesses a memory page that is not currently loaded in physical RAM, requiring the OS to retrieve it from disk.  
**Paging / Page:** Dividing virtual and physical memory into fixed-size blocks (pages) so memory can be mapped and swapped between RAM and disk.  
**Paradigm:** A foundational style or methodology for structuring and writing programs (such as imperative, object-oriented, functional, or logic).  
**Parsing (Syntax Tree):** The compilation phase that analyzes token structure against grammar rules, typically building a syntax tree.  
**Permissive Licence (e.g., MIT):** A software license with minimal restrictions on reuse and modification, generally permitting inclusion in proprietary works.  
**Polymorphism:** The ability for different entities or types to respond to the same interface or operation in type-specific ways.  
**Primary Key (PK):** A column or set of columns that uniquely identifies each row in a table.  
**Process:** A program currently in execution, along with its runtime state and allocated resources.  
**Proprietary (Closed-Source) Software:** Software whose source code remains privately owned and restricted by a vendor or organization, typically distributed as compiled binaries under a license.  
**Pseudocode:** An informal, structured outline of an algorithm written in plain language mixed with code-like conventions.  

## Q

**Quantum:** The fixed time slice allocated to a process in round-robin scheduling before it yields or moves to the back of the ready queue.  
**Query:** A request or statement issued to a database to retrieve, insert, update, or delete data.  

## R

**RAM (Random Access Memory):** Fast, volatile main memory used to hold active programs and data currently being processed by the CPU.  
**Rapid Elasticity:** The ability to scale computing resources up or down quickly—often automatically—to match changing demand.  
**Recursion:** A technique in which a function calls itself to solve a problem by breaking it down into smaller subproblems.  
**Redundancy:** Duplicating the same data across multiple places in a database.  
**Relational Model / Relational Database:** A data model organizing information into tables (relations) of rows and columns with relationships established via keys.  
**Repository (Repo):** A storage location (local or remote) containing a project's files and version history.  
**Resource Pooling:** Sharing provider computing resources across multiple consumers dynamically assigned and reassigned according to demand.  
**Round Robin:** A CPU scheduling policy that assigns each ready process a fixed time slice in cyclic order.  
**Row (Tuple):** A single record within a table representing one instance of the entity.  

## S

**SaaS (Software as a Service):** A cloud service model where providers host and run applications centrally, and users access them via a client such as a web browser.  
**Scheduler:** The OS component that selects which ready process is assigned to the CPU next.  
**Schema:** The formal structure or blueprint defining tables, columns, data types, keys, and relationships in a database.  
**SDLC (Software Development Life Cycle):** The structured lifecycle for planning, designing, coding, testing, releasing, and maintaining software.  
**Semantic Checks:** Verification stages that check logical validity and type/meaning rules beyond basic grammatical structure.  
**Server:** A dedicated computer system that provides data, services, or hosted applications to other computers (clients) over a network.  
**Software:** Intangible sets of digital instructions, rules, and data stored on hardware that direct how physical components operate.  
**Software Licence:** Legal terms governing how software may be used, modified, distributed, or commercialized.  
**Source Code / Source Text:** The original human-written code files before translation or compilation into executable form.  
**Spiral Model:** A risk-driven process model that cycles through planning, risk analysis, engineering, and evaluation.  
**SQL (Structured Query Language):** A declarative language used to define, query, and manipulate data in relational databases.  
**Synchronisation (Sync):** Keeping data consistent across multiple devices or locations automatically.  
**Syntax:** The formal rules governing the structure and valid arrangement of symbols and keywords in a programming language.  
**System Architecture:** The high-level structural design defining a system's components, interfaces, data flow, and interactions.  
**System Software:** Foundational software positioned between hardware and applications that manages core resources (such as memory, processor time, and storage) and provides a user interface.  
**System Test:** End-to-end testing of the complete, integrated software system against specifications.  

## T

**Table (Relation):** A structured set of data organized into rows and columns representing an entity or relationship.  
**The Cloud:** Pooled, remote computing resources—such as servers, storage, and networking—delivered over the internet.  
**Time-Sharing:** A multi-user computing model where multiple users interact with a system simultaneously by sharing CPU time via rapid switching.  
**Transaction:** A sequence of database operations executed as a single logical unit of work that either completes entirely or rolls back.  
**Transistor:** A semiconductor switch inside a processor that toggles electrical states to represent and process binary signals.  

## U

**Unit Test:** Automated or targeted testing of an individual function or smallest testable unit in isolation.  
**UNIX:** A foundational multi-user, multitasking operating system that heavily influenced modern operating systems.  
**Update Anomalies:** Inconsistencies or errors that arise during inserts, updates, or deletes when redundant data is not updated uniformly.  
**User Interface (UI):** The visual or interactive layer—such as windows, icons, menus, and controls—through which users interact with software.  

## V

**Variables:** Named storage references in a program that hold values which can be read or updated during execution.  
**Vendor Lock-In:** Dependency on a single provider's proprietary tools, formats, or ecosystem that makes switching providers costly or difficult.  
**Version Control:** A system that tracks revisions to files over time, enabling history inspection, branching, and rollback.  
**Virtual Machine (VM):** A software-based execution environment that emulates a computer or runs bytecode independently of underlying hardware specifics.  
**Virtual Memory:** A memory management technique that decouples logical address space from physical RAM, allowing programs to use more address space than physical RAM by storing inactive data on disk.  

## W

**Waterfall Model:** A sequential software development model where each phase is completed before moving to the next.  
**White-Box Testing:** Testing software with visibility into internal code paths, logic, and structure.  

# Algorithms and Data Structures  

## A
**Abstract Data Type (ADT)** — A description of *what* a structure does (its operations) without saying *how* it is built. A stack is an ADT with `push` and `pop`; it can be built with an array or a linked list.  
**Adjacency List** — A graph representation that stores, for each vertex, a list of its neighbors. Space O(V + E); best for sparse graphs.  
**Adjacency Matrix** — A V × V table for a graph, with 1 where an edge exists. Space O(V²); edge check in O(1); best for dense graphs.  
**Algorithm** — A finite, ordered sequence of precise, executable steps that takes some input and produces the desired output.  
**al-Khwarizmi** — The 9th-century Persian mathematician whose name gives us the word "algorithm."  
**Amortized O(1)** — Average cost per operation over many operations, even if an occasional operation is expensive (such as appending to a dynamic array that sometimes resizes).  
**Array** — A fixed number of same-type elements stored in consecutive memory locations, each identified by an index. Gives O(1) random access.  
**AVL Tree** — A self-balancing binary search tree that rotates nodes after inserts and deletes so subtree heights differ by at most 1.  
**Average Case** — The cost of an algorithm on a typical input.  

## B
**B-tree** — A multi-way balanced tree with many keys per node, designed for disks. Used in databases and file systems.  
**Backtracking** — A design strategy that builds a solution step by step and undoes a step when it cannot work (N-queens, Sudoku, maze solving).  
**Balanced Tree** — A tree where the heights of the two subtrees of every node differ by at most a small constant.  
**Base Case** — The simple instance of a recursive problem that is answered directly and stops the recursion.  
**Base Address** — The memory address of an array's first element, used to compute the address of element i.  
**Best Case** — The most favorable input for an algorithm.  
**Big-O Notation** — A way to describe how cost grows with input size by keeping only the fastest-growing term and dropping constant factors. So 3n² + 5n + 20 is O(n²).  
**Binary Heap** — A complete binary tree stored in an array that obeys the heap property.  
**Binary Search** — A search on a sorted array that compares the target with the middle item and discards half the range each step. Time O(log n).  
**Binary Search Tree (BST)** — A binary tree where, for every node, all keys in the left subtree are smaller and all keys in the right subtree are larger.  
**Binary Tree** — A tree in which every node has at most two children, called left and right.  
**Breadth-First Search (BFS)** — A graph or tree traversal that visits nodes level by level, using a queue. Finds the fewest-edge path in unweighted graphs. Time O(V + E).  
**Brute Force** — A design strategy that tries every possibility.  
**Bubble Sort** — Repeatedly swaps adjacent out-of-order items so the largest remaining item "bubbles" to the end. O(n²) worst and average, O(n) best with early exit. Stable.  
**Buffer Overflow** — A security hole caused by accessing an array index beyond its end in languages like C.  

## C
**Call Stack** — The memory structure where each function call is pushed with its own variables and waits until the call it made returns.  
**Circular Linked List** — A linked list whose last node points back to the first.  
**Circular Queue** — A fixed-size queue with wrap-around indexes, using `rear = (rear + 1) mod capacity`. Used for buffers.  
**Comparison Sort** — A sort that orders items only by comparing pairs. None can beat O(n log n) in the worst case.  
**Complete Binary Tree** — A binary tree with all levels full except possibly the last, which is filled left to right.  
**Correctness** — The property that an algorithm produces the right output for every valid input.  
**Counting Sort** — A non-comparison sort that runs in O(n + k) when keys are small integers in a range of size k.  
**Cycle** — A path in a graph that returns to its starting vertex. Trees have none.  

## D
**Data Structure** — A way of organizing, storing, and accessing data so that operations on it are efficient.  
**Definiteness** — The property that every step of an algorithm is precisely and unambiguously defined.  
**Degenerate (Skewed) Tree** — A tree in which every node has one child, so it behaves like a linked list.  
**Degree** — The number of children of a node.  
**Depth (of a node)** — The number of edges from the root to that node.  
**Depth-First Search (DFS)** — A traversal that goes as deep as possible along one branch, then backtracks. Uses a stack or recursion. Time O(V + E).  
**Deque (Double-Ended Queue)** — A queue where items can be added and removed at both ends.  
**Dequeue** — The queue operation that removes and returns the front item.  
**Dijkstra's Algorithm** — A shortest-path algorithm (1959) for weighted graphs that uses a priority queue.  
**Directed Graph** — A graph whose edges have a direction.  
**Divide and Conquer** — A design strategy that splits a problem into smaller subproblems, solves each, and combines the results (binary search, merge sort, quick sort).  
**Doubly Linked List** — A linked list whose nodes have both `next` and `prev` references, allowing travel in both directions.  
**Dynamic Array** — An array that hides a fixed array and allocates a larger one (typically about double) when full. Python `list`, Java `ArrayList`, C++ `vector`.  
**Dynamic Programming** — A design strategy that solves overlapping subproblems once and stores the answers (memoized Fibonacci, knapsack, edit distance).  
**Dynamic Structure** — A structure whose size changes at run time.  

## E
**Edge** — A connection between two nodes in a tree or two vertices in a graph.  
**Effectiveness** — The property that each step of an algorithm is basic enough to be carried out exactly.  
**Enqueue** — The queue operation that adds an item at the rear.  
**Euclid's Algorithm** — One of the oldest algorithms still in use, for the greatest common divisor, using gcd(a, b) = gcd(b, a mod b).  
**Expression Tree** — A tree representing an arithmetic expression. In-order gives the expression and post-order gives postfix.  
**Exponential Time (O(2ⁿ))** — A growth rate so fast that even n = 100 is impractical.  

## F
**Factorial Time (O(n!))** — A growth rate seen when trying every ordering of n items, such as cities.  
**Fibonacci (recursive)** — A classic example of recursion that repeats work. `fib(30)` makes about 2.7 million calls without memoization.  
**FIFO (First-In, First-Out)** — The ordering of a queue: the first item added is the first removed.  
**Finiteness** — The property that an algorithm ends after a finite number of steps.  
**Flowchart** — A diagram of an algorithm using symbols (oval, rectangle, parallelogram, diamond, arrow).  
**Full Binary Tree** — A binary tree where every node has 0 or 2 children.  

## G
**Generality** — The property that an algorithm solves a whole class of problems, not one instance.  
**Graph** — A set of vertices and the edges connecting pairs of them. May contain cycles and have no root.  
**Greedy Algorithm** — A design strategy that takes the locally best choice at each step. It is correct only for problems with the right structure; for coins {1, 3, 4} and amount 6 it gives 3 coins instead of the optimal 2.  

## H
**Halting Problem** — A problem proven unsolvable by any algorithm (Turing, 1936).  
**Hash Table** — A structure that finds items in O(1) average time by computing an index from the key. Mentioned as an extension.  
**Head** — The first node of a linked list, through which the list is accessed.  
**Heap Property** — In a min-heap, every parent is less than or equal to its children (reverse for a max-heap).  
**Heap Sort** — A sort that uses a heap. O(n log n) in all cases, O(1) extra space, not stable.  
**Height (of a tree)** — The number of edges on the longest root-to-leaf path.  
**Heuristic** — A method that gives a good but not always optimal answer, used for hard problems.  

## I
**In-order Traversal** — Binary tree order: left subtree, node, right subtree. On a BST it gives sorted output.  
**In-order Successor** — The smallest key in a node's right subtree, used when deleting a BST node with two children.  
**In-place** — Using only O(1) (or O(log n)) extra memory.  
**Input** — Zero or more clearly specified values an algorithm starts with.  
**Insertion Sort** — Grows a sorted prefix by sliding each next item left past larger items. O(n²) worst, O(n) on nearly sorted data. Stable.  
**Internal Node** — A tree node with at least one child.  
**Intractable Problem** — A problem with no known efficient algorithm, such as brute-forcing the traveling salesman problem.  
**Iteration** — Repeating a block of steps with a loop.  

## L
**Leaf** — A tree node with no children.  
**Level-order Traversal** — Visiting a tree level by level, using a queue. Also called breadth-first.  
**LIFO (Last-In, First-Out)** — The ordering of a stack: the last item added is the first removed.  
**Linear Search** — Checks each item in order until the target is found or items run out. O(n); works on any list.  
**Linear Structure** — A structure whose items form a sequence, each with one predecessor and one successor (array, linked list, stack, queue).  
**Linked List** — A chain of nodes, each holding a value and a reference to the next node.  
**Logarithmic Time (O(log n))** — A growth rate where each step halves the problem, as in binary search.  
**Loop Invariant** — A statement that is true before and after every pass of a loop. The main tool for proving a loop correct.  

## M
**Memoization** — Storing each result the first time it is computed so it is never recomputed. Does not change answers.  
**Merge Sort** — Splits a list in half, sorts each half recursively, then merges them. O(n log n) in every case, O(n) space. Stable.  
**Min-Heap** — A heap where the smallest item is at the root.  

## N
**Node** — A record in a linked list, tree, or graph, typically holding a value and references to other nodes.  
**Non-linear Structure** — A structure where items are connected in a hierarchy or network (tree, graph).  

## O
**Off-by-One Error** — Running a loop one pass too many or too few, or using the wrong array index.  
**Output** — At least one result related to the input.  
**Overflow (stack)** — Pushing onto a full fixed-size stack. See also *Stack Overflow*.  

## P
**Path** — A sequence of connected nodes.  
**Perfect Binary Tree** — A full binary tree in which all leaves are on the same level.  
**Pivot** — The item chosen in quick sort to partition the list into smaller and larger items.  
**Pop** — The stack operation that removes and returns the top item.  
**Post-order Traversal** — Visiting children first, then the node. In a binary tree: left, right, node.  
**Postfix Notation** — Writing an operator after its operands, so no parentheses are needed. Evaluated with a stack.  
**Pre-order Traversal** — Visiting the node first, then its children.  
**Priority Queue** — A queue where items leave by priority rather than arrival order, usually implemented with a heap.  
**Program** — An algorithm written in a programming language so a computer can run it.  
**Pseudocode** — A precise, language-independent way to write an algorithm. It cannot be run.  
**Push** — The stack operation that places an item on top.  

## Q
**Quadratic Time (O(n²))** — A growth rate seen in bubble, selection, and insertion sort.  
**Queue** — A collection with first-in, first-out order: items are added at the rear and removed from the front.  
**Quick Sort** — Chooses a pivot, partitions the list, then sorts each side recursively. O(n log n) average, O(n²) worst case. Usually not stable.  

## R
**Random Access** — Reaching any element directly in O(1) time, as in an array.  
**Record (Struct, Tuple, Object)** — A group of named fields, possibly of different types, describing one entity.  
**Recursion** — Solving a problem by having a function call itself on a smaller instance.  
**Recursive Case** — The part of a recursive function that reduces the problem to a smaller instance and combines the result.  
**Red-Black Tree** — A balanced binary search tree that colors nodes so the longest path is at most twice the shortest.  
**Root** — The top node of a tree, with no parent.  
**Row-Major Order** — Storing a 2D array row by row. Element (i, j) is at base + (i × cols + j) × element size.  

## S
**Searching** — Finding the position of a target value in a collection, or reporting that it is absent.  
**Selection (control structure)** — Choosing a path by a condition, such as `if ... then ... else`.  
**Selection Sort** — Finds the smallest item in the unsorted part and swaps it into place. O(n²) in all cases, at most n − 1 swaps. Not stable.  
**Sequence (control structure)** — Steps carried out one after another.  
**Siblings** — Tree nodes that share the same parent.  
**Singly Linked List** — A linked list where each node has only a `next` reference.  
**Sorting** — Rearranging items into a defined order.  
**Space Complexity** — How much extra memory an algorithm needs as input size n grows.  
**Stable Sort** — A sort in which items with equal keys keep their original relative order.  
**Stack** — A collection with last-in, first-out order, where only the top is accessible.  
**Stack Overflow** — An error caused by recursion that never reaches its base case, or by going too deep. Python limits depth to 1,000 calls by default.  
**Static Structure** — A structure whose size is fixed at creation, such as a classic array.  
**Structured Programming** — Programming with only sequence, selection, and iteration (Böhm and Jacopini, 1966).  
**Subtree** — A node together with all its descendants.  

## T
**Tail Recursion** — Recursion where the recursive call is the last action, so some compilers can reuse the stack frame. Python does not optimize it.  
**Time Complexity** — How the number of basic operations grows with input size n.  
**Towers of Hanoi** — A naturally recursive puzzle needing 2ⁿ − 1 moves for n disks.  
**Traversal** — Visiting every node of a tree or graph once.  
**Tree** — A hierarchical, non-linear structure of nodes connected by edges, with one root and no cycles. A tree with n nodes has n − 1 edges.  

## U
**Underflow (stack)** — Popping an empty stack.  
**Undirected Graph** — A graph whose edges have no direction.  
**Undecidable Problem** — A problem that no algorithm can solve in general, such as the halting problem.  

## V
**Vertex** — A node in a graph.  

## W
**Weighted Graph** — A graph whose edges carry values such as distance or cost.  
**Worst Case** — The least favorable input for an algorithm. The usual default for analysis because it gives a guarantee.

# Symbolic AI

## A
**A\* Search** — An informed search that orders the frontier by f(n) = g(n) + h(n). It is optimal when h is admissible (tree search) or consistent (graph search). Weakness: high memory use.  
**Action** — Something an agent can do in a state, described with preconditions and effects.  
**Add List** — In STRIPS, the facts that become true after an action is applied.  
**Admissible Heuristic** — A heuristic h(n) that never overestimates the true remaining cost to the goal. Straight-line distance is an example.  
**Adversarial Search** — Search used when another agent opposes the agent's actions, as in two-player games such as chess.  
**Agent (Semantic Role)** — The participant who performs an action. In "The cat chased the mouse," the agent is *cat*.  
**Alpha-Beta Pruning** — An optimization of minimax that returns the same decision while skipping branches that cannot affect it. A branch is cut when α ≥ β.  
**Ambiguity** — A sentence or word that has more than one valid interpretation (for example, "I saw the man with the telescope"). A central difficulty for rule-based NLP.  
**Antecedent** — The "if" part (premise p) of an implication p → q.  
**Artificial Intelligence Winter (AI Winter)** — The late-1980s to 1990s collapse in funding after expert systems proved costly to maintain and brittle.  

## B
**Backtracking Search** — A CSP method that assigns variables one at a time and undoes (backtracks) an assignment when a constraint is violated.  
**Backward Chaining** — Goal-driven reasoning that starts from a hypothesis and checks whether the facts support it. Like a doctor asking "could it be flu?"  
**Backward (Regression) Search** — A planning strategy that starts from the goal and finds actions that could produce it, replacing the goal with their preconditions.  
**Biconditional (p ↔ q)** — "p if and only if q." True when p and q have the same truth value.  
**Boolean Operators** — AND (∧), OR (∨), and NOT (¬), used to combine propositions.  
**Boolean Query** — An information retrieval query that combines terms with AND, OR, and NOT.  
**Branching Factor (b)** — The number of actions available in each state.  
**Breadth-First Search (BFS)** — Expands the shallowest unexpanded node first, using a queue. Complete, and optimal when all steps cost the same, but memory-hungry.  
**Brittleness** — The tendency of a system to fail outside its narrow domain or when input differs slightly from what its rules expect.  

## C
**Certainty Factor** — A number expressing how confident a system is in a conclusion, used by MYCIN (for example, "organism is E. coli, certainty 0.7").  
**Chart Parsing (CYK, Earley)** — A parsing approach that stores partial results in a table so that no sub-phrase is parsed twice. Worst-case time is cubic in sentence length.  
**Chomsky Hierarchy** — Chomsky's (1956) classification of formal grammars by power: regular, context-free, context-sensitive, and unrestricted.  
**Classical Planning** — Planning under the assumptions that the world is deterministic, fully observable, static, discrete, and has a single agent.  
**Closed List** — See *Explored Set*.  
**Closed-World Assumption** — In STRIPS, anything not listed as true is assumed false.  
**Combinatorial Explosion** — The rapid growth in the number of states to examine (about b^d) as depth grows, making large searches intractable.  
**Commonsense Knowledge** — Obvious everyday knowledge that humans have but that is hard to write down as rules (the Cyc project tried for decades).  
**Completeness** — A search property: if a solution exists, the algorithm is guaranteed to find it.  
**Compositional Semantics** — Building the meaning of a sentence from the meanings of its parts, following the parse structure.  
**Conflict Resolution** — How an inference engine chooses among several rules that can fire at once, by priority, specificity, or recency.  
**Consequent** — The "then" part (conclusion q) of an implication p → q.  
**Consistent Heuristic** — A heuristic where h(n) ≤ c + h(n') for every step from n to n' with cost c. Consistency implies admissibility.  
**Constraint** — A rule restricting which combinations of variable values are allowed in a CSP.  
**Constraint Propagation** — Removing values that can no longer work (for example forward checking, arc consistency) to detect dead ends early.  
**Constraint Satisfaction Problem (CSP)** — A problem defined by variables, a domain of values for each, and constraints on combinations. Map colouring is the standard example.  
**Context-Free Grammar (CFG)** — A grammar whose rules have a single symbol on the left side. The standard workhorse of syntactic parsing.  

## D
**Dartmouth Conference (1956)** — The meeting that named the field "artificial intelligence."  
**De Morgan's Laws** — ¬(p ∧ q) ≡ ¬p ∨ ¬q and ¬(p ∨ q) ≡ ¬p ∧ ¬q.  
**Deep Blue** — The IBM chess system that beat world champion Garry Kasparov in 1997 using deep alpha-beta search, special hardware, and a hand-built evaluation function.  
**DENDRAL** — A 1960s system that worked out organic molecule structures from mass spectrometer data. Often called the first expert system.  
**Delete List** — In STRIPS, the facts that become false after an action is applied.  
**Depth (d)** — The number of steps to the shallowest goal.  
**Depth-First Search (DFS)** — Expands the deepest unexpanded node first, using a stack or recursion. Small memory use but not optimal.  
**Depth-Limited Search** — DFS with a cutoff depth l, which avoids endless descent.  
**Dependency Grammar** — A grammar that links each word to its head word.  
**Discourse and Pragmatics** — The level of language analysis concerned with context and intent (for example, "Can you pass the salt?" is a request).  
**Domination (of heuristics)** — Heuristic h2 dominates h1 if h2(n) ≥ h1(n) for all n while staying admissible, so h2 expands fewer nodes.  
**Double Negation** — The equivalence ¬(¬p) ≡ p.  

## E
**ELIZA** — A 1966 chatbot by Weizenbaum that used keyword spotting and decomposition and reassembly rules to imitate a psychotherapist.  
**Evaluation Function** — A heuristic score for a game position, used when the search stops at a depth limit (for chess, material count and piece positions).  
**Existential Generalization (EG)** — From P(c) ∧ Q(c) for a specific c, conclude ∃x(P(x) ∧ Q(x)). Always safe.  
**Existential Instantiation (EI)** — From ∃x(P(x) ∧ Q(x)), name a specific element c that satisfies it. The name c must be new.  
**Existential Quantifier (∃)** — "There exists": true for at least one element in the domain.  
**Expanding a Node** — Generating all of a node's children.  
**Expert System** — An AI system that emulates the decision-making of a human expert in one specific domain.  
**Explainability** — The ability to trace and show how a system reached a conclusion. A key strength of symbolic AI.  
**Explored Set (Closed List)** — States already expanded, kept so that the search does not loop.  

## F
**Forward Chaining** — Data-driven reasoning that starts from known facts and moves toward conclusions. Like a detective collecting clues.  
**Forward (Progression) Search** — A planning strategy that starts at the initial state and applies applicable actions toward the goal.  
**Frame** — A data structure for a stereotypical object or situation, with slots (properties), values, and default values.  
**Frame Problem** — The difficulty of stating everything that does *not* change when an action occurs.  
**Frontier (Open List)** — Nodes that have been generated but not yet expanded.  

## G
**General Problem Solver (GPS)** — A 1957 program that attempted general-purpose problem solving and introduced means-ends analysis.  
**Global Maximum** — The best state anywhere in the state-space landscape.  
**GOFAI (Good Old-Fashioned AI)** — Another name for symbolic AI.  
**Goal State** — The desired state a plan or search tries to reach.  
**Goal Test** — How to recognize that a state is a goal.  
**Greedy Best-First Search** — Orders the frontier by f(n) = h(n) only. Fast but neither optimal nor complete.  
**Gazetteer** — A list of known names, places, or organizations used alongside patterns in information extraction.  

## H
**Heuristic** — A rule of thumb or domain knowledge used to guide search. It is not a guarantee.  
**Heuristic Function h(n)** — An estimate of the cost of the cheapest path from node n to a goal.  
**Hierarchical Task Network (HTN)** — A planning approach that breaks high-level tasks into subtasks using expert-written methods.  
**Hill Climbing** — A local search that always moves to a better neighbor and stops when none is better. It can get stuck at local maxima, ridges, and plateaus.  
**Hypernym / Hyponym** — In WordNet, a more general word (*mammal* for *cat*) and a more specific word (*cat* for *mammal*).  

## I
**Implication (p → q)** — "If p, then q." False only when p is true and q is false.  
**Inference Engine** — The reasoning program that applies rules to facts to derive conclusions.  
**Inference Rule** — A pattern that lets us derive new conclusions from known statements (for example Modus Ponens).  
**Informed (Heuristic) Search** — Search that uses domain-specific knowledge to expand the most promising nodes first.  
**Information Extraction (IE)** — Identifying specific entities and relationships in unstructured text using predefined patterns.  
**Information Retrieval (IR)** — Finding relevant documents in large collections.  
**Initial State** — Where the agent starts.  
**Iterative Deepening Search** — Runs depth-limited search with l = 0, 1, 2, ... until a goal is found. Combines BFS's completeness with DFS's small memory.  

## K
**Knowledge Acquisition Bottleneck** — The slow, expensive process of extracting knowledge from experts and writing it down as rules.  
**Knowledge Base** — The stored facts and rules of a symbolic system.  
**Knowledge Engineer** — The person who builds the knowledge base from an expert's expertise.  
**Knowledge Graph** — Entities and labeled relations, used for question answering and retrieval. A modern descendant of ontologies and semantic networks.  
**Knowledge Representation** — How an AI system stores knowledge in a form it can reason with.  

## L
**Lexicon** — A dictionary of words with part of speech, forms, and features.  
**LISP** — The main AI programming language for decades, created by John McCarthy in 1958.  
**Local Maximum** — A state better than all its neighbors but not the best overall.  
**Local Search** — Search that keeps a single current solution and moves to neighboring ones. Used when only the final state matters.  
**Logic Theorist** — A 1956 program (Newell, Simon, Shaw) that proved mathematical theorems using heuristic search.  
**Logic-Based Representation** — Knowledge written as propositional logic or first-order logic.  
**Logical Equivalence (≡)** — Two statements that have the same truth value in every situation.  
**Logical Form** — A formal representation of a sentence's meaning, such as `Chased(cat1, mouse1)`.  

## M
**MAX / MIN** — The two players in minimax. MAX tries to maximize the score and MIN tries to minimize it.  
**Means-Ends Analysis** — A planning method that compares the current state with the goal, picks an action that reduces the difference, and makes its preconditions new subgoals.  
**Minimax** — An adversarial search that passes values up a game tree, with MAX taking the largest child value and MIN the smallest. It assumes the opponent plays its best move.  
**Modus Ponens** — From p → q and p, conclude q.  
**Modus Tollens** — From p → q and ¬q, conclude ¬p.  
**Morphological Analysis** — Finding word structure and base forms (chased = chase + past tense).  
**MYCIN** — A 1970s expert system that diagnosed bacterial blood infections using roughly 600 rules and certainty factors.  

## N
**Natural Language Processing (NLP)** — The field concerned with computers understanding, interpreting, and generating human language.  
**Negation (in sentiment rules)** — A rule that flips polarity, as in "not good."  
**Neuro-Symbolic AI** — Approaches that combine symbolic reasoning with neural networks.  
**Node** — A state plus bookkeeping such as parent node, action taken, and path cost so far.  

## O
**Ontology** — A formal representation of the concepts in a domain and their relationships, giving a shared vocabulary.  
**Open List** — See *Frontier*.  
**Optimality** — A search property: the algorithm finds the lowest-cost solution.  
**Optimal Solution** — The solution path with the lowest path cost.  

## P
**Parse Tree** — A tree showing the hierarchical structure of a sentence according to a grammar.  
**Parsing** — Finding a parse tree for a sentence according to a grammar. Can be top-down, bottom-up, or chart-based.  
**Part-of-Speech (POS) Tagging** — Assigning each word a grammatical category such as noun or verb.  
**Partial-Order Planning** — A planning method that orders actions only where necessary ("least commitment").  
**Patient (Semantic Role)** — The participant acted upon. In "The cat chased the mouse," the patient is *mouse*.  
**Path Cost** — A number measuring how good a path is, such as total distance.  
**PDDL (Planning Domain Definition Language)** — The standard language for describing planning problems, used in the International Planning Competition.  
**Plan** — A sequence of actions that transforms an initial state into a goal state.  
**Planning** — Finding a sequence of actions that reaches a goal state from an initial state.  
**Planning Graph (GraphPlan)** — A compact layered structure of what could be true at each step, from which a plan is extracted.  
**Plateau** — A flat area in the state-space landscape with no direction to move.  
**Precondition** — A fact that must hold for an action to be applicable.  
**Predicate** — A statement with variables that is true or false depending on their values, such as Even(x).  
**Predicate Logic (First-Order Logic)** — Logic that adds predicates, variables, and quantifiers to propositional logic.  
**Production Rule** — An IF-THEN rule with a condition and an action.  
**Prolog** — A logic programming language that appeared in 1972.  
**Proposition** — A declarative sentence that is either true or false, but not both.  
**Propositional Logic** — Logic about whole statements combined with Boolean operators.  

## Q
**Qualification Problem** — The difficulty of listing every condition that must hold for an action to work.  
**Quantifier** — A symbol (∀ or ∃) stating how many elements a predicate applies to.  
**Question Answering (QA)** — Systems that interpret a natural-language question and infer the answer, often from formal knowledge.  

## R
**Ramification Problem** — The difficulty of capturing the indirect effects of actions.  
**Relaxed Problem** — A simpler version of a problem with some rules removed. Its exact solution cost makes a good admissible heuristic.  
**Ridge** — A narrow slope that rises sideways, which single steps cannot climb.  
**Rule-Based System (Production System)** — A system that operates on a set of IF-THEN rules.  

## S
**Script** — A sequence of frames describing a typical chain of events, such as going to a restaurant.  
**Semantic Network** — A graph where nodes are concepts and links are relationships.  
**Semantic Role** — The part a participant plays in an event, such as agent or patient.  
**Semantics** — The meaning conveyed by words, phrases, and sentences in context.  
**Sentiment Analysis** — Determining the emotional tone (positive, negative, neutral) of text.  
**Sentiment Lexicon** — A list of words with polarity scores.  
**SHRDLU** — A 1972 system by Winograd that carried out typed commands in a simulated blocks world.  
**Simulated Annealing** — A local search that sometimes accepts worse moves with probability e^(−Δ/T), lowering the temperature T over time to escape local maxima.  
**State Space** — The set of all states reachable from the initial state by any sequence of actions.  
**State-Space Landscape** — A picture where each state has a height given by an objective function.  
**STRIPS** — A 1971 planner (Fikes and Nilsson) that describes actions by preconditions, a delete list, and an add list.  
**Sub-Symbolic AI (Connectionist)** — AI that stores knowledge as numerical weights in a network and learns from data, such as neural networks.  
**Symbolic AI** — AI in which knowledge is written explicitly as symbols, rules, and logic, and the computer reasons by manipulating them.  
**Synset** — In WordNet, a set of synonyms.  
**Syntax** — The structure of language: how words and phrases form grammatical sentences.  

## T
**Terminal Test** — In a game, the check for whether the game is over.  
**Tokenization** — Splitting text into words and punctuation.  
**Transition Model** — The state that results from applying an action in a state.  
**Transposition Table** — A store of positions already evaluated, since different move orders can reach the same position.  
**Truth Table** — A table listing the truth value of a compound statement for every combination of inputs.  

## U
**Uniform-Cost Search (UCS)** — Expands the node with the lowest path cost g(n). It is BFS generalized to steps of different cost.  
**Uninformed (Blind) Search** — Search that uses no knowledge of the goal beyond the problem definition.  
**Universal Generalization (UG)** — From P(a) → Q(a), conclude ∀x(P(x) → Q(x)). Valid only if a is arbitrary.  
**Universal Instantiation (UI)** — From a statement about all x, conclude it for a specific element a. Always safe.  
**Universal Modus Ponens** — From ∀x(P(x)→Q(x)) and P(a), conclude Q(a).  
**Universal Modus Tollens** — From ∀x(P(x)→Q(x)) and ¬Q(a), conclude ¬P(a).  
**Universal Quantifier (∀)** — "For all": true for every element in the domain.  
**Utility** — The final score of a game outcome (for example +1 win, 0 draw, −1 loss).  

## W
**Well-Defined Problem** — A problem with five parts: initial state, actions, transition model, goal test, and path cost.  
**Word Sense Disambiguation** — Choosing the correct meaning of a word from context.  
**WordNet** — A symbolic lexical resource that groups words into synsets linked by relations such as hypernym and meronym.  
**Working Memory** — Holds the facts about the current case in a rule-based system.  

## X
**XCON / R1** — A 1980s expert system that configured computer orders for Digital Equipment Corporation.  

## Z
**Zero-Sum Game** — A game in which one player's gain is exactly the other's loss.
