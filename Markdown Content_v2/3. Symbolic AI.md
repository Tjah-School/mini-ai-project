## **Introduction to Symbolic AI**

### **6.1 What Symbolic AI Is**

#### **6.1.1 Definition**

**Symbolic AI** is the approach to artificial intelligence in which knowledge is written down explicitly as **symbols, rules, and logic**, and the computer reasons by manipulating those symbols. It is also called **GOFAI (Good Old-Fashioned AI)** and was the dominant approach from the 1950s to the 1980s.

#### **6.1.2 Core Idea: Representation and Manipulation of Symbols**

The idea has two parts:

1. **Representation.** Facts about the world are encoded as symbols a computer can store. For example, `Human(Socrates)` or “fever” and “cough”.  
2. **Manipulation.** The computer applies logical rules to those symbols to produce new knowledge.

The classic example:

* Fact: `Human(Socrates)`  
* Rule: `∀x (Human(x) → Mortal(x))`  
* Conclusion: `Mortal(Socrates)`

Nobody trained the system on examples. It reached the conclusion by following rules, the way a person works through a proof. The underlying belief is that human thinking is largely symbol manipulation, so a machine that does the same can behave intelligently.

#### **6.1.3 Contrast with Sub-Symbolic AI (Connectionist/Neural)**

|  | Symbolic AI | Sub-symbolic AI |
| ----- | ----- | ----- |
| Knowledge is stored as | Explicit rules, logic, symbols | Numerical weights in a network |
| Where knowledge comes from | Written by humans | Learned from data |
| Reasoning | Step-by-step logical inference | Pattern recognition |
| Explainability | High; you can trace each step | Low; often a “black box” |
| Handles noisy or uncertain data | Poorly | Well |
| Typical examples | Expert systems, theorem provers | Neural networks, deep learning, LLMs |

#### In short, symbolic AI is told what to know, while sub-symbolic AI learns what to know.

#### **6.1.4 Goal of Symbolic AI**

The goal is to build systems that can **reason, make decisions, and solve problems** using human-readable knowledge, and to **explain** how they reached a conclusion. It aims to capture expert knowledge (a doctor’s diagnostic rules, for example) so a machine can apply it consistently.

### **6.2 History**

* **1956:** The Dartmouth Conference names the field “artificial intelligence.” The **Logic Theorist** (Newell, Simon, Shaw) proves mathematical theorems.  
* **1957:** The **General Problem Solver (GPS)** attempts general-purpose problem solving.  
* **1958:** John McCarthy creates **LISP**, the main AI language for decades.  
* **1960s:** Early rule-based programs appear, such as **ELIZA** (pattern-matching chatbot) and **DENDRAL** (infers chemical structures).  
* **1970s:** **MYCIN** diagnoses blood infections with roughly hundreds of if-then rules. Minsky proposes **frames** for knowledge representation, and **Prolog** appears (1972), a logic programming language.  
* **1980s:** The **expert systems boom**. Companies deploy systems like XCON, which configured computer orders for DEC.  
* **Late 1980s to 1990s:** Expert systems prove costly to maintain and brittle, and funding collapses (the **AI winter**). Machine learning takes over.  
* **Today:** Symbolic ideas survive in knowledge graphs, planning, and **neuro-symbolic AI**.

### **6.3 How Symbolic AI Works (in General)**

A symbolic system has three main parts:

1. **Knowledge base:** the stored facts and rules.  
2. **Inference engine:** the reasoning program that applies rules to facts to derive conclusions.  
3. **Interface:** how users enter facts and receive answers, often with an explanation.

**Worked example (from your lecture slides):**  
 `IF fever AND cough AND difficulty breathing THEN possible pneumonia`

1. The user reports symptoms (new facts).  
2. The inference engine checks which rules match.  
3. The pneumonia rule fires, and the conclusion “possible pneumonia” is added.  
4. The system can show the rule that led there.

Two reasoning styles are worth knowing:

* **Forward chaining:** start from known facts and move toward conclusions.  
* **Backward chaining:** start from a hypothesis (such as “pneumonia?”) and check whether the facts support it.

### **Strengths and Limitations, Explained**

**Strengths**

* **Interpretability:** every conclusion traces to specific rules, which matters in medicine, law, and finance.  
* **Structured knowledge:** complex domain knowledge can be formalized clearly.  
* **Flexibility:** you change behavior by editing rules, with no retraining.

**Limitations**

* **Incomplete knowledge:** if a rule is missing, the system fails rather than guessing.  
* **Scalability:** thousands of interacting rules become slow and hard to maintain.  
* **Uncertainty:** it expects clean true/false facts, so vague input like “kind of tired” is hard to handle.  
* **No learning:** humans must hand-write every rule (the *knowledge acquisition bottleneck*).







## **Logic and Reasoning**

**Why Logic Matters**

Symbolic AI represents knowledge as logical statements, and logic supplies the rules for reasoning from them. The deck covers two levels: **propositional logic** (whole statements) and **predicate logic** (statements about objects and their properties).

---

### **Part A: Propositional Logic** 

### **1\. Propositions** 

A **proposition** is a declarative sentence that is **either true or false, but not both**.

* Propositions: “The sky is blue.” / “It is raining.” / “2 \+ 2 \= 4.”  
* Not propositions: questions (“Is it raining?”) and commands (“Close the door”), because they have no truth value.

By convention, propositions are given letters such as **p** and **q**.

#### **2\. Boolean Operators** 

Operators combine propositions. Using the notes’ example, **p** \= “It is raining” and **q** \= “It is windy”:

| Operator | Symbol | Meaning | Example |
| ----- | ----- | ----- | ----- |
| AND | p ∧ q | True only if **both** are true | “It is raining and windy” |
| OR | p ∨ q | True if **at least one** is true | “It is raining or windy” |
| NOT | ¬p | Flips the truth value | “It is not raining” |

Truth table:

| p | q | p ∧ q | p ∨ q | ¬p |
| ----- | ----- | ----- | ----- | ----- |
| T | T | T | T | F |
| T | F | F | T | F |
| F | T | F | T | T |
| F | F | F | F | T |

#### **3\. Logical Equivalences** 

Two statements are **equivalent (≡)** if they have the same truth value in every situation.

* **De Morgan’s Laws**  
  * ¬(p ∧ q) ≡ ¬p ∨ ¬q (“not both” means “at least one is not”)  
  * ¬(p ∨ q) ≡ ¬p ∧ ¬q (“neither” means “both are not”)  
* **Double Negation:** ¬(¬p) ≡ p

Example: “It is not true that it is raining **and** windy” is the same as “It is not raining **or** it is not windy.”

#### **4\. Implication and Biconditional** 

#### **Implication (p → q):** “if p, then q.” **p** is the *antecedent* (premise) and **q** is the *consequent* (conclusion).

* Example: “If it is raining, then the ground is wet.”  
  * It is **false only when p is true and q is false** (raining but the ground is dry). In every other case it is true.  
* **Biconditional (p ↔ q):** “p if and only if q.” p and q always have the **same truth value**.  
  * Example: “You can access the system if and only if you have the correct password.”

| p | q | p → q | p ↔ q |
| ----- | ----- | ----- | ----- |
| T | T | T | T |
| T | F | **F** | F |
| F | T | T | F |
| F | F | T | T |

#### **5\. Inference Rules** 

**Inference rules** let us derive new conclusions from known statements.

| Rule | Latin meaning | Pattern | Example |
| ----- | ----- | ----- | ----- |
| **Modus Ponens** | “mode that affirms” | p → q, and p is true ⟹ **q** is true | “If it rains, the ground is wet.” It is raining, so the ground is wet. |
| **Modus Tollens** | “mode that denies” | p → q, and q is false ⟹ **p** is false | “If it rains, the ground is wet.” The ground is dry, so it is not raining. |

#### 

#### **6\. Role in AI** 

* **Knowledge representation:** facts become propositions, such as “the lights are on” or “the door is locked” in a smart home.  
* **Logical inference:** from “if the traffic light is red, then stop” and “the traffic light is red,” a self-driving system infers “stop the vehicle.”

### **Part B: Predicate Logic**

#### **Why we need it**

Propositional logic can’t say “all cats are mammals” in a general way. Predicate logic can, because it adds **variables, predicates, and quantifiers**.

#### **1\. Predicates and Quantifiers**

* **Predicate:** a statement with variables that is true or false depending on their values. Example: **Even(x)** is true when x is an even number.  
* **Universal quantifier (∀):** true for **all** elements in the domain.  
  * ∀x (Cat(x) → Mammal(x)) means “every cat is a mammal.”  
* **Existential quantifier (∃):** true for **at least one** element.  
  * ∃x (Prime(x) ∧ x \< 10\) means “some prime number is less than 10.”

Memory aid: ∀ is an upside-down **A** (“for **A**ll”) and ∃ is a backwards **E** (“there **E**xists”).

#### **2\. Translating English into Logic** 

Four steps:

1. **Identify the predicates** (properties or relationships).  
2. **Introduce variables** for the objects involved.  
3. **Apply quantifiers** (all or at least one).  
4. **Formulate the expression.**

Example: “Some birds can fly” becomes **∃y (Bird(y) ∧ CanFly(y))**, meaning there is at least one y that is a bird and can fly.

Tip: ∀ usually pairs with **→** and ∃ usually pairs with **∧**.

#### **3\. Logical Connectives** 

Predicate logic uses the same connectives (∧, ∨, →, ¬) to build complex statements:

* Even(x) ∧ Prime(x): x is even and prime  
* Positive(x) ∨ Negative(x): x is positive or negative  
* Adult(x) → CanVote(x): if x is an adult, x can vote  
* ¬Married(x): x is not married  
* ∀x (Even(x) → Positive(x)): every even number is positive

**Note:** the last example on your slide, ∀x(Even(x) → Positive(x)) ∧ Prime(x), has a scope problem. The ∧ Prime(x) sits outside the quantifier, so that x is unbound. Written correctly it would be ∀x((Even(x) → Positive(x)) ∧ Prime(x)), which is probably a deliberate “spot the error” example, but check with your instructor.

#### **4\. Instantiation** 

* **Universal Instantiation (UI):** from a statement about *all* x, conclude it for a *specific* element a.  
  * ∀x(P(x) → Q(x)) ⟹ P(a) → Q(a)  
  * “All humans are mortal” ⟹ “If Socrates is human, he is mortal.”  
* **Existential Instantiation (EI):** from “something exists,” name a specific element c that satisfies it.  
  * ∃x(P(x) ∧ Q(x)) ⟹ P(c) ∧ Q(c)  
  * Here **c must be a new name** not already used. You know *something* satisfies it, but not which thing.

#### **5\. Generalization** 

* **Universal Generalization (UG):** P(a) → Q(a) ⟹ ∀x(P(x) → Q(x))  
* **Existential Generalization (EG):** P(c) ∧ Q(c) ⟹ ∃x(P(x) ∧ Q(x))

**“Do you see anything strange for the above 4 rules?”** Here is the likely answer:

* **UI and EG are always safe.** Going from “all” to one, or from one to “there exists,” never loses truth.  
* **UG is risky.** Showing something for *one* element doesn’t prove it for *all*. “3 is odd and prime” doesn’t mean everything is. UG is valid **only if a is arbitrary**, meaning you assumed nothing special about it.  
* **EI is restricted.** The constant c must be fresh, because you only know *some* element works.

So the four rules are not symmetrical: two are unrestricted and two come with conditions.

#### **6\. Applications** 

* ∀n (Even(n)): every number is even (a false statement, but valid logic)  
* ∃x (x ∈ S ∧ x \> 10): the set S has an element greater than 10  
* ∃x (Honest(x) ∧ Trustworthy(x)): someone is honest and trustworthy  
* ∀o (Car(o) → HasFourWheels(o)): every car has four wheels

This shows a statement can be well-formed and still false. Logic tests structure, not truth in the real world.

#### **7\. Rules of Inference in Predicate Logic (Slide 20\)**

| Rule | Given | Conclude |
| ----- | ----- | ----- |
| **Universal Modus Ponens** | ∀x(P(x)→Q(x)) and P(a) | Q(a) |
| **Universal Modus Tollens** | ∀x(P(x)→Q(x)) and ¬Q(a) | ¬P(a) |
| **Existential Instantiation** | ∃xP(x) | P(c) for a specific c |
| **Existential Generalization** | P(c) for a specific c | ∃xP(x) |

Example of Universal Modus Ponens: “All humans are mortal” and “Socrates is human” give “Socrates is mortal.”

### **Propositional vs. Predicate Logic**

|  | Propositional | Predicate (First-Order) |
| ----- | ----- | ----- |
| Basic unit | Whole statements (p, q) | Predicates, variables, objects |
| Quantifiers | None | ∀ and ∃ |
| Expressiveness | Limited | Much richer |
| Can say “all cats are mammals”? | No | Yes |
| Complexity | Simpler, decidable | More powerful, harder to automate |
