## **2\. Algorithms**

### **2.1 Algorithm fundamentals, representation and efficiency**

**Learning objectives**

* Define an algorithm and list its five characteristics.  
* Represent an algorithm as a flowchart, pseudocode and code.  
* Read basic Big-O notation and tell time from space.

**Core concepts**

* An **algorithm** is a finite, ordered set of unambiguous, executable steps that solves a problem. **Characteristics (extra, after Knuth):** finiteness, definiteness, input, output, effectiveness.  
* **Representation (slides):** natural language; **flowchart** (oval \= start/end, parallelogram \= input/output, rectangle \= process, diamond \= decision); **pseudocode** (structured, language-independent); real code.  
* **Algorithm versus program:** the algorithm is the abstract method; a program is one implementation of it in a language.  
* **Efficiency (extra):** *time* (steps) and *space* (memory). **Big-O** describes growth with input size n: O(1) constant, O(log n), O(n), O(n log n), O(n²). Best, average and worst cases can differ.  
* **Correctness comes first:** an incorrect fast algorithm is useless; a correct algorithm is then compared by efficiency.  
* **Design strategies (extra):** brute force, divide and conquer, greedy, dynamic programming.

**Real-world analogy: a recipe.** Ingredients \= input, finished dish \= output, numbered steps \= definite and finite, "cook until golden" is vague (not definite), so a precise recipe says "bake 20 minutes at 180°C".

**Worked example (find the maximum).**

max ← first item  
for each remaining item x:  
    if x \> max: max ← x  
return max  
Trace on \[3, 9, 4\]: max=3 → 9 \> 3 so max=9 → 4 \> 9 no → return 9\. It looks at each item once, so time is O(n), space O(1).

**True / False**

1. An algorithm must finish after a finite number of steps.  
2. An algorithm and a program are exactly the same thing.  
3. Pseudocode must obey the exact syntax of one specific programming language.  
4. In a flowchart, a diamond normally represents a decision.  
5. Big-O notation describes how the resources an algorithm needs grow as input size grows.

**Multiple Choice**

1. Which is NOT a required algorithm characteristic? (a) finiteness (b) definiteness (c) effectiveness (d) being the fastest possible solution  
2. Which representation is readable and language-independent? (a) machine code (b) pseudocode (c) binary (d) assembly  
3. An algorithm whose running time doubles when its input doubles is: (a) O(1) (b) O(n) (c) O(n²) (d) O(log n)  
4. A parallelogram in a standard flowchart usually shows: (a) a decision (b) start/end (c) input/output (d) a loop counter  
5. The maximum-finding algorithm in the worked example uses how much extra memory? (a) O(n) (b) O(n²) (c) O(1) (d) O(log n)

**Open-ended**

1. Define an algorithm and explain its five characteristics using everyday steps such as withdrawing cash. Compare flowcharts and pseudocode as representations, and explain why two correct algorithms may still differ.

**Answer key**

* T/F: 1 True. 2 False. 3 False. 4 True. 5 True.  
* MC: 1 d. 2 b. 3 b. 4 c. 5 c.  
* Open-ended: all five characteristics illustrated; flowchart \= visual control flow, pseudocode \= compact and easy to code; differ in time and space.

**Further reading:** Cormen, Leiserson, Rivest & Stein, *Introduction to Algorithms*, MIT Press; Brookshear & Brylow (algorithm chapter).

### **2.2 Basic algorithms: sorting and searching**

**Learning objectives**

* Trace bubble sort and binary search by hand.  
* Compare the main sorting algorithms by idea and cost.  
* Explain why binary search needs sorted data.

**Core concepts**

* **Sorting (slides: sorting, searching):** *bubble* (swap neighbouring out-of-order items), *selection* (pick the smallest remaining), *insertion* (insert each item into the sorted part), *merge sort* and *quick sort* (divide and conquer).  
* **Costs (extra):** bubble, selection and insertion are O(n²) in the worst case; merge sort is O(n log n) always; quick sort is O(n log n) on average and O(n²) in the worst case.  
* **Searching:** *linear search* checks items in turn, O(n); *binary search* compares with the middle of a **sorted** list and discards half each step, O(log n).  
* **Stable sort (extra):** equal items keep their original order; merge sort and insertion sort are stable.

**Real-world analogy.** Looking up a word in a paper dictionary: you open near the middle, decide the word is earlier or later, and halve the pages: binary search. Reading every page from the front is linear search.

**Worked example.** Bubble sort pass on \[5, 1, 4, 2\]: (5,1) swap → \[1,5,4,2\]; (5,4) swap → \[1,4,5,2\]; (5,2) swap → \[1,4,2,5\]. The largest item has "bubbled" to the end. Binary search for 23 in \[2, 5, 8, 12, 16, 23, 38\]: low=0, high=6, mid=3 (12 \< 23\) → low=4; mid=5 (23) found in two steps.

**True / False**

1. Binary search requires the data to be sorted.  
2. Selection sort repeatedly picks the smallest remaining element and places it next.  
3. Merge sort is based on divide and conquer.  
4. Bubble sort has an average running time of O(n log n).  
5. Linear search can be used on unsorted data.

**Multiple Choice**

1. After one full bubble-sort pass on \[5, 1, 4, 2\], the list is: (a) \[1, 2, 4, 5\] (b) \[1, 4, 2, 5\] (c) \[5, 4, 2, 1\] (d) \[2, 1, 4, 5\]  
2. Roughly how many halvings does binary search need for 1,024 sorted items in the worst case? (a) 10 (b) 32 (c) 512 (d) 1,024  
3. Which sort has guaranteed O(n log n) time? (a) bubble sort (b) merge sort (c) selection sort (d) insertion sort  
4. In binary search of \[2, 5, 8, 12, 16, 23, 38\] for 23, the first middle element compared is: (a) 5 (b) 12 (c) 23 (d) 38  
5. A stable sort: (a) never swaps (b) keeps the original order of equal items (c) is always the fastest (d) needs no extra steps

**Open-ended**

1. Explain why binary search is faster than linear search on large sorted data, and describe how you would sort a list of student marks with merge sort, with a small example.

**Answer key**

* T/F: 1 True. 2 True. 3 True. 4 False (O(n²)). 5 True.  
* MC: 1 b. 2 a. 3 b. 4 b. 5 b.  
* Open-ended: halving versus scanning; merge sort splits into halves, sorts each, merges.

**Further reading:** Cormen et al., *Introduction to Algorithms* (sorting and searching chapters).

### **2.3 Linear data structures: arrays, records, linked lists, stacks and queues**

**Learning objectives**

* Describe each structure's layout and operations.  
* Compare cost of access, insertion and deletion.  
* Match a structure to a real use.

**Core concepts**

* **Array (slides):** same-type elements in contiguous memory, direct access by index in O(1); inserting in the middle shifts items, O(n).  
* **Record (slides):** a group of named fields that may have different types (e.g. name, age, ID).  
* **Linked list (slides):** nodes holding data plus a pointer to the next node. Grows dynamically; insertion or deletion at a known node is O(1); reaching the n-th item needs traversal, O(n). Variants: doubly linked, circular *(extra)*.  
* **Stack (slides):** last in, first out (LIFO); push, pop, peek.  
* **Queue (slides):** first in, first out (FIFO); enqueue, dequeue. Variants: deque, priority queue *(extra)*.  
* **Practical note:** Python's documentation shows a list used as a stack with append and pop, and says a list is not efficient as a queue; it suggests collections.deque for that.

**Real-world analogy.** Array \= a row of numbered lockers; linked list \= a treasure hunt where each clue points to the next; stack \= a pile of plates; queue \= a ticket line.

**Worked example.** Push A, B, C; pop twice: C, then B come out; only A remains. Enqueue A, B, C; dequeue twice: A, then B come out; C remains.

**True / False**

1. Array elements are stored contiguously and can be accessed directly by index.  
2. A record must contain elements that are all of the same type.  
3. A linked list can grow dynamically without pre-allocating a fixed size.  
4. A stack follows the first-in, first-out principle.  
5. A queue removes the element that was added earliest.

**Multiple Choice**

1. The "undo" feature of an editor is most naturally a: (a) queue (b) stack (c) array of records (d) binary tree  
2. A print-job list handled in arrival order is a: (a) queue (b) stack (c) tree (d) graph  
3. Each node of a singly linked list contains: (a) only data (b) data and a pointer to the next node (c) only a pointer (d) an index table  
4. The main disadvantage of a linked list compared with an array is: (a) it cannot store data (b) no direct index access, so you traverse from the head (c) it has a fixed size (d) it cannot be changed  
5. After pushing A, B, C and popping twice, the stack contains: (a) A (b) B (c) C (d) nothing

**Open-ended**

1. Compare arrays and linked lists for memory layout, access and insertion. Which would you choose for a playlist with frequent insertions, and where would a stack and a queue appear in a music app?

**Answer key**

* T/F: 1 True. 2 False. 3 True. 4 False (that is a queue). 5 True.  
* MC: 1 b. 2 a. 3 b. 4 b. 5 a.  
* Open-ended: array \= contiguous, O(1) access, costly insert; linked list \= pointers, cheap insert, O(n) access; playlist → linked list; "play next" queue, back-history stack.

### **2.4 Iteration and recursion**

**Learning objectives**

* Write the same computation with a loop and with recursion.  
* Identify base case and recursive case.  
* Explain call-stack cost and when each style fits.

**Core concepts**

* **Iteration (slides)** repeats a block with for or while. **Recursion (slides)** solves a problem by calling the same function on a smaller input.  
* A recursive function needs a **base case** (stops the calls) and a **recursive case** that moves toward it. Without a base case the calls never stop and the stack overflows.  
* **Call stack (extra):** each active call gets a stack frame. Deep recursion uses more memory than a loop.  
* **Equivalence (extra):** any recursion can be rewritten with loops and an explicit stack, and vice versa.  
* **Classic cases (extra):** factorial, Fibonacci (the naive version repeats work and is exponential), Tower of Hanoi (2ⁿ − 1 moves for n discs).  
* **When to choose:** recursion for naturally nested structures (trees, divide and conquer); loops for simple repetition.

**Real-world analogy: Russian nesting dolls.** Opening each doll is the recursive case; the smallest solid doll is the base case.

**Worked example (sum of 1..n).** Iterative: total=0; for i in 1..n: total \+= i. Recursive: sum(n) \= n \+ sum(n−1), sum(0) \= 0. sum(3) \= 3 \+ sum(2) \= 3 \+ (2 \+ sum(1)) \= 3 \+ (2 \+ (1 \+ sum(0))) \= 6.

**True / False**

1. A recursive function with no base case will eventually stop normally.  
2. Every recursive solution can be rewritten iteratively.  
3. Each active recursive call uses a stack frame.  
4. The naive recursive Fibonacci function is efficient because it never repeats work.  
5. Moving n discs in the Tower of Hanoi needs 2ⁿ − 1 moves.

**Multiple Choice**

1. Which part stops a recursion? (a) the loop counter (b) the base case (c) the return type (d) a comment  
2. With sum(n) \= n \+ sum(n−1) and sum(0) \= 0, sum(4) \= (a) 4 (b) 6 (c) 10 (d) 24  
3. Deep recursion can use a lot of memory mainly because of: (a) call-stack frames (b) longer source code (c) disk fragmentation (d) network delay  
4. Which problem naturally suits recursion? (a) printing 1 to 10 (b) walking through a nested folder tree (c) adding two numbers (d) reading a single file  
5. The recursive case of a recursive function must: (a) call itself on a problem closer to the base case (b) call itself on a larger problem (c) never call itself (d) always print output

**Open-ended**

1. Write both a loop and a recursive version of factorial. Compare readability, memory use and risk of failure, and say which you would use for a very large n and why.

**Answer key**

* T/F: 1 False (it recurses until the stack overflows). 2 True. 3 True. 4 False (it repeats subproblems). 5 True.  
* MC: 1 b. 2 c (4+3+2+1+0 \= 10). 3 a. 4 b. 5 a.  
* Open-ended: loop uses constant extra memory; recursion maps closely to the definition but costs stack frames; for large n prefer the loop.

**Further reading:** Python Tutorial, Data Structures (recursion-friendly list operations): https\://docs.python.org/3/tutorial/datastructures.html

### **2.5 Trees, graphs and breadth-first search (BFS)**

**Learning objectives**

* Describe trees, binary trees and graphs with terminology.  
* Perform the three binary-tree traversals.  
* Run BFS by hand using a queue.

**Core concepts**

* **Tree (slides):** hierarchical; one **root**; every other node has exactly one **parent**; nodes without children are **leaves**; **height** is the longest root-to-leaf path.  
* **Binary tree (slides):** at most two children per node. **Traversals (extra):** pre-order (node, left, right), in-order (left, node, right), post-order (left, right, node). In a **binary search tree**, in-order gives sorted keys.  
* **Graph (slides):** **vertices** joined by **edges**; directed or undirected, weighted or unweighted; may contain cycles. Stored as an **adjacency matrix** or **adjacency list** *(extra)*.  
* **BFS (slides: BFS sample material):** visits vertices level by level using a **queue**; on an unweighted graph it finds paths with the fewest edges. **DFS** goes deep first using a stack or recursion *(extra)*.  
* **Note:** BFS and DFS are also used to search state spaces in AI; 3.8 builds on this and does not re-explain them.

**Real-world analogy.** A tree is a company chart; a graph is a subway map; BFS finds the fewest-stops route.

**Worked example (BFS).** Graph edges: A–B, A–C, B–D, C–D, D–E. Start at A. Queue: \[A\]. Visit A, enqueue B, C → \[B, C\]. Visit B, enqueue D → \[C, D\]. Visit C (D already seen) → \[D\]. Visit D, enqueue E → \[E\]. Visit E. Order: A, B, C, D, E; shortest A→E path has 3 edges (A–B–D–E).

**True / False**

1. In a tree, every node except the root has exactly one parent.  
2. A binary-tree node may have up to three children.  
3. In-order traversal of a binary search tree visits keys in ascending order.  
4. A graph may contain cycles, but a tree may not.  
5. BFS uses a stack to hold the vertices waiting to be visited.

**Multiple Choice**

1. A node with no children is a: (a) root (b) leaf (c) parent (d) edge  
2. Friendships on a social network such as Weixin are best modelled as: (a) a stack (b) an undirected graph (c) a sorted array (d) a record  
3. On an unweighted graph, BFS from a start vertex finds: (a) the longest path (b) the path with the fewest edges to each reachable vertex (c) only the first leaf (d) a sorted list  
4. A tree has root A, left child B, right child C, and B has a left child D. Its pre-order traversal is: (a) A B D C (b) D B A C (c) D B C A (d) A C B D  
5. In the BFS example above, the 3rd vertex visited is: (a) D (b) E (c) C (d) B

**Open-ended**

1. Explain BFS on a graph of at least six vertices, showing the queue after each step. Distinguish trees from graphs and give one real application of BFS.

**Answer key**

* T/F: 1 True. 2 False (two). 3 True. 4 True. 5 False (a queue).  
* MC: 1 b. 2 b. 3 b. 4 a. 5 c (A, B, C).
